# L2 JEV 层：有界选择

**定位**：规则弃权时，从**有限候选集**里挑一个。
**不是**自由生成——JEV 只能在给定选项里选，输出受约束。

代码：`src/lorwright/decide/jev.py`、`decide/jev_policy.py`

---

## 一、为什么用 JEV 而不是直接上 LLM

| 维度 | JEV | LLM |
|---|---|---|
| 延迟 | 100–500ms | 2–20s |
| 输出 | 受约束（必须选一个候选） | 自由文本，需要解析 |
| 成本 | 低 | 高 |
| 失败模式 | 返回 None → 降级 | 幻觉、格式错、超时 |

**回合制对局里 500ms 完全可接受，20s 会让对局节奏崩掉。**

---

## 二、接口契约

### 请求

```json
POST {base_url}/decide
Authorization: Bearer {api_key}
Content-Type: application/json

{
  "kind": "choice",
  "context": "局面描述（见第三节）",
  "options": ["打出 尖啸蜘蛛（2 费）", "打出 群蛛之主（5 费）", "结束回合"]
}
```

### 响应

```json
{ "choice": "打出 尖啸蜘蛛（2 费）" }
```

### 约束

| 项 | 规则 |
|---|---|
| `choice` 必须 ∈ `options` | 否则视为失败，降级 |
| 超时 | 2s（可配） |
| 失败 | 返回 `None`，路由跳到下一层 |

**布尔决策**（`kind: "noul"`）返回 `{"value": true|false}`，暂未使用。

---

## 三、上下文格式

`state.summary()` 目前只给一行。**JEV 需要更完整的结构化上下文**，
建议扩展成：

```
回合 3 | 我方 50 血 | 敌方 30 血 | 法力 2/3（法术槽 0）
我方场面：无
敌方场面：5/7 化学庞克撕裂乐手
手牌（6 张）：
  - 尖啸蜘蛛 2 费 2/2（召唤时+2/+0）
  - 伊莉丝 2 费 2/3（挑战者）
  - 倾巢而出 6 费 法术
  - 群蛛之主 5 费 6/6
  - 尖啸蜘蛛 2 费 2/2
  - 蛛网 3 费 法术
可出：尖啸蜘蛛、伊莉丝、尖啸蜘蛛
```

**关键**：上下文里要包含**卡牌效果文本**，否则 JEV 不知道「召唤时+2/+0」意味着什么。

---

## 四、候选生成

`decide/candidates.py::generate(state)`：

| 候选 | 条件 |
|---|---|
| `PLAY_CARD` | 每张 `cost <= mana` 的牌 |
| `ATTACK nexus` | 有 `can_attack` 单位 |
| `END_TURN` | 永远有 |

**候选数 ≤ 1 时不调 JEV**（没得选，直接返回）。

---

## 五、降级链路

```
L1 穷举/规则  ──弃权──▶  L2 JEV  ──失败──▶  L3 LLM  ──失败──▶  NO_OP
                              │                 │                  │
                        超时/非法选项     不在已知标签里      不动，等下一 tick
```

**每一层都可弃权，任何一层失败都不阻塞主循环。**

### 但 L3 不是「让 LLM 看着画面点」

L1 → L2 回答的是「选哪个**动作**」。L3 回答的是另一个问题：
**「现在是什么界面？」**

这是有意的：

| 问题 | 为什么不能交给 LLM |
|---|---|
| 延迟 2–20s | 回来时画面早变了，你点的是过期坐标 |
| 自由文本输出 | 无法校验、无法回滚、无法单测 |
| 状态不明时点击 | 2026-11-02 就是这样点进了设定菜单 |

所以 L3 的契约也是**有界选择**，只是候选不是动作而是界面标签：

```
输入：截图 + 已知界面标签列表
输出：{"label": "battle"}      # 必须 ∈ labels
```

命中已知界面 → 交给对应决策点的确定性逻辑；
仍不认识 → `NO_OP` + 存快照 + 停下等人。

### 「卡住」不走这条链

画面连续 N 帧不变是**像素问题，不是语义问题**。由并行的监督器处理：

```
Watchdog（截图哈希 / state.summary() 不变）
      ↓
RecoveryPolicy（重试 → 重开对局 → 重启客户端 → 停）
```

纯状态机，可单测，不调任何模型。
**LLM 不决定重启几次、重启什么。**

## 六、配置

`config/settings.yaml`：

```yaml
jev_base_url: ""      # 例：https://your-jev-endpoint/v1
jev_api_key: ""       # 你后续提供
```

**留空 = 不启用，路由直接跳过 L2。**

---

## 七、验证步骤

| 阶段 | 做法 | 通过标准 |
|---|---|---|
| 1. Mock | `MockJev(answer="...")` | 路由正确选中，30 个单测全绿 |
| 2. 连通 | 真实 endpoint + 1 条固定 context | 返回合法 `choice` |
| 3. 覆盖率 | 跑 20 局，统计各层命中 | L2 命中 15–25% |
| 4. 合法性 | 记录所有非法选项 | 非法率 < 5% |

**现在停在阶段 1**——`MockJev` 已可用，真实 endpoint 等你配 key。
