# L1 规则层：蜘蛛快攻（v2）

**定位**：确定性决策。**凡是能精确求解的，都不该进 L2。**
**原则**：纯函数（只读 state，返回 Action），可单测，不碰网络/截图/文件。

代码：`src/lorwright/decide/rules.py::SpiderAggroPolicy`
战斗求解器：`src/lorwright/decide/combat.py`

> v1 的问题：8 条扁平规则混了 5 个不同的决策点，其中 3 条动作在 LoR 里根本不存在，
> 1 条是死规则。v2 改成「先分派决策点，再套该点的规则」。

---

## 一、先纠正一个前提：LoR 不是「回合制」

LoR 用的是**交替优先权（alternating priority）**，不是「我的回合 / 对手的回合」。

| 界面状态 | 含义 | 我能做什么 |
|---|---|---|
| 大蓝按钮 + 文字「結束回合」 | 我持有优先权，且对手已让过 → 按下即结束本轮 | 出牌、攻击、结束回合 |
| 大蓝按钮 + 文字「略過」 | 我持有优先权，但对手还没让过 → 按下只是把优先权交给对手 | 出牌、攻击、让过 |
| 没有蓝按钮 / 按钮变暗 | **对手持有优先权** | **没有合法动作** |

所以：

- **「不是我的回合就不操作」是对的**——不是我保守，是规则上你没有合法动作可做。
- 但 v1 把它写成「弃权（返回 `None`）」是**错的**。没有优先权时答案唯一，就是 `NO_OP`。
  弃权会让路由把这条请求继续送到 JEV / LLM，**在对手回合每一帧都白烧一次网络调用**。
  → **R0 必须 `return Action(NO_OP)`，不是 `None`。**
- 变量名 `MY_TURN_IDLE` 也是错的：它实际表示「我持有优先权」，应改叫 `MY_PRIORITY`。
  对手回合里我拿到响应窗口时，按钮同样变蓝——这就是同一个状态。

**待验证**（在 F1 上做）：点「略過」后是否立刻进入敌方动作。若是，则「略過 = 我方优先权」成立。

### 一个连带 bug

`Watchdog` 用 `state.summary()` 判卡死。对手回合连续 3 帧 `NO_OP` 时摘要不变 →
会被判成「卡住」，刷快照甚至触发重开。**`NO_OP` 不应计入卡死计数。**

## 二、8 条规则体检

| # | 结论 | 问题 |
|---|---|---|
| R1 斩杀 | ⚠️ 算错 | `sum(atk) >= enemy_hp` 忽略了**对手分配格挡**。攻击力总和 ≠ 打脸伤害 |
| R2 保命 | ❌ 动作不存在 | LoR 里没有「攻击某个单位」。对手攻击时我做的是**分配格挡**，是另一种动作 |
| R3 铺场 | ✅ 基本合理 | 但评分公式没算关键词和召唤效果；上限 6 正确 |
| R4 优势交换 | ❌ 动作不存在 | 同上。只有带**挑战者（Challenger）**的单位才能选格挡者；`atk>=3` 是无依据的魔数 |
| R5 抢血 | ⚠️ 条件错 | `总攻 > 敌方总血` 既不充分也不必要。LoR 攻击几乎无成本（单位不会因攻击力竭），快攻默认就该每次有令牌都打 |
| R6 法术补刀 | ⚠️ 太粗 | 缺伤害值/目标血量/是否需要选目标；3 费换一个 2/2 对快攻是亏的 |
| R7 空手 | ✅ 合理 | 但定义要改成「没有可打出的牌」而非「手牌为空」 |
| R8 存法力 | ❌ 死规则 | **LoR 法力不结转**，回合结束即清空。「存法力」这个机制不存在。且已被 R7 覆盖 |

**净结果：8 条里 3 条有硬错误、1 条是死规则、2 条动作不存在。**

### 为什么 R2 / R4 是硬错误

LoR 的战斗是**攻方声明攻击者 → 守方分配格挡者**。攻方无法指定「打哪个单位」。

唯一的例外是**挑战者（Challenger）**：带这个关键词的单位攻击时，由攻方指定谁来挡它。

所以 R2 / R4 描述的动作在语义层就缺一个 `BLOCK` 动作类型——
这不是规则写错，是 `ActionType` 里少了一个枚举值。

## 三、v2 结构：按决策点分派

扁平优先级列表表达不了「格挡阶段 R1 无意义」。改成：

```
P0 守卫      → 我在哪个决策点？（优先权 / 换牌 / 出牌 / 攻击 / 格挡 / 选目标）
P1 换牌
P2 攻击声明   ← 精确解
P3 格挡声明   ← 精确解
P4 出牌       ← 唯一真正需要 L2 的地方
P5 目标选择   ← 精确解
```

### P0 守卫

```
if ui_state != MY_PRIORITY: return NO_OP          # 没有优先权，唯一合法动作
if 换牌界面:              → P1
if 攻击声明界面:          → P2
if 格挡声明界面:          → P3
if 需要选目标:            → P5
if 我方优先权:            → P4
```

**起手换牌界面当前会被误判成「我方优先权」**（「確定」按钮和动作按钮位置重叠，见 `docs/status.md`）。
这是 P0 必须先修的 bug——否则开局第一秒机器人就会去点牌。

## 四、把「可枚举的」变成精确解

这是让 L1 吃掉更多、而不是靠加 if 的关键。LoR 的动作空间小到可以穷举：

| 决策点 | 搜索空间 | 规模 | 实测（6v6） | 归属 |
|---|---|---|---|---|
| 格挡分配 | ≤6 格挡者 → ≤6 攻击者 | ≤ 13,327 种分配 | 17 ms | **L1 精确解** |
| 攻击者子集 | 2^6−1 = 63 种声明 × 对手最优格挡 | 63 × 13k | 23 ms | **L1 精确解** |
| 斩杀判定 | 同上，取最大脸伤 | 免费 | 24 ms | **L1 精确解** |
| 法术目标 | ≤6 | 6 | <1 ms | **L1 精确解** |
| 换牌 | 2^4 = 16 | 16 | <1 ms | **L1 精确解** |
| 本回合怎么花光法力 | 手牌子集 × 顺序 | 组合爆炸 | — | L1 贪心 + L2 兜底 |

（实测环境：Python 3.11 / M 系列 Mac，2v2 到 6v6 全规模都跑过。
6v6 是最坏情况，24 ms，tick 预算 200 ms——**穷举比启发式既准又便宜，没有理由不穷举**。）

**结论：R1 / R4 / R5 合并成同一个「攻击声明求解器」。**
斩杀不再是手写规则，而是求解器的**副产品**：最优攻击声明打出的脸伤 ≥ 敌方水晶血量，就是斩杀。

这样三条规则变成一个算法，不会出现「规则说能斩、求解器算出不能」的自相矛盾。

### 战斗结算模型（`decide/combat.py`）

支持关键词：普通 / 灵巧(Elusive) / 恐惧(Fearsome) / 挑战者(Challenger) / 碾压(Overwhelm) / 快速攻击(Quick Attack) / 坚韧(Tough)

- 格挡合法性：灵巧攻击者只能被灵巧挡；恐惧攻击者只能被攻击力 ≥3 的挡
- 快速攻击：若先手伤害足以击杀格挡者，则不受伤
- 坚韧：受到的伤害 −1
- 碾压：对格挡者的溢出伤害穿透到水晶
- 未被格挡：全额攻击力打到水晶

**守方目标（字典序）**：先最小化自己水晶受到的伤害，再最大化「我方存活价值 − 对方存活价值」。
**攻方目标**：最大化「打出的脸伤 − 我方损失价值 + 对方损失价值」。

## 五、P4 出牌：唯一需要 L2 的地方

出牌阶段真正难的只有一件事：**这张牌的效果文本值不值得现在出**。

规则能做的（L1）：

| # | 名称 | 条件 | 动作 |
|---|---|---|---|
| P4-a | **buff 优先** | 手上同时有「给其他蜘蛛 buff」的牌和普通单位牌 | 先出 buff 牌 |
| P4-b | 铺场 | 有单位牌可出 且 `len(my_units) < 6` | 打出评分最高的单位 |
| P4-c | 花光法力 | 还有法力 且 有可出的牌 | 贪心继续出 |
| P4-d | 收尾 | 没有可出的牌 | `END_TURN` |

### 评分公式（已按伊莉丝牌组重写）

v1 的 `atk*2 + hp - cost*1.5` 把这套牌当「纯快攻」算，**是错的**。
这套牌的收益结构是 **buff 叠乘**：群蛛之主 +2/+0、尖啸蜘蛛 +2/+0、
發狂疾行蛛 +1/+0，都是「喂给其他蜘蛛」的。所以评分必须含「场上蜘蛛数」。

```
score(card) =
    atk + hp
  + 群蛛之主     : + 2 × (场上蜘蛛数 − 1)      # 每多喂一只多赚 2 攻
  + 尖啸蜘蛛     : + 2 × 场上蜘蛛数            # 本回合攻击前出，等于全体 +2
  + 發狂疾行蛛   : + 1 × 场上蜘蛛数 + 1        # 顺带削对面 1 攻
  + 倾巢而出     : + 3（三只小蜘蛛）+ 场上蜘蛛数
  + 蜘蛛哨兵/蜘術士 : + 2 × max(0, 对面最大攻击力 − 3)   # 击晕大单位才值
  − cost × 1.5
```

完整牌表与每张牌的效果见 `docs/decks/spider-aggro.md`。

**已删除 v1 的 R6「法术补刀」**：这套牌**没有任何直伤法术**，
只有泰尔石（生成三选一）和倾巢而出（召唤），R6 永远不会触发。

**弃权给 L2 的条件**（这些才真的需要理解卡牌文本）：

| 场景 | 为什么规则处理不了 |
|---|---|
| 同费牌 score 差 < 1 | 数值上无法区分，需要看效果文本 |
| 群蛛之主 vs 尖啸蜘蛛 先出哪个 | 两者都是 buff，先手顺序需要算两层 |
| 泰尔石该不该现在开 | 开了要选三张里的哪张，还占 1 费节奏 |
| 该不该留击晕牌应对对手下回合 | 需要对手手牌信息 |

### 已知未建模（不阻塞，但会算偏）

| 未建模 | 影响 | 为什么先不做 |
|---|---|---|
| 尖啸蜘蛛的「攻击时全体 +2\|+0」 | 攻击声明的脸伤会算少 | 「Spider allies」是否包含自身存在歧义，需实测确认 |
| 伊莉丝的「攻击：召唤小蜘蛛」 | 攻击收益会算少一只 1/1 | 同上，且召唤位置影响格挡合法性 |
| 挑战者单位实际选哪个格挡者 | `chooser="attacker"` 已支持，但感知层还没解析 `challenger` | 需要击晕/挑战者图标模板 |
| 泰尔石的三选一 | 开了就默认选 +2\|+2 | 需要额外一张选牌界面截图才能标定 |

这些都属于「算偏一点」，不会让机器人做出危险动作（比如误点菜单）。
先上真机跑通主循环，再回来补。

## 六、状态字段硬依赖

规则再漂亮，字段解析不出来就是空转。当前 `Engine._build_state()` **只填了 `ui_state`**，
其余全是默认值（`mana=0`、`hand=[]`、`my_units=[]`、`hp=20/20`）——
所以策略实际上永远走「手牌为空 → 结束回合」。这是 issue #4 的根因。

| 字段 | 类型 | 来源 | 用途 | 状态 |
|---|---|---|---|---|
| `ui_state` | 枚举 | 颜色探针 | P0 守卫 | ✅ 已有 |
| `button_text` | 結束回合/略過 | 按钮文字 OCR | 是否结束本轮 | ❌ 待做 |
| `mana` / `max_mana` | int | 右侧数字 | 可出牌判定 | ❌ |
| `spell_mana` | int | 右侧法术槽 | 法术可出判定 | ❌ |
| `hand[].cost` | int | 卡面左上 | 费用过滤 | ❌ |
| `hand[].kind` | 单位/法术 | 卡面边框色 | 分流 | ❌ |
| `hand[].keywords` | set | 卡面关键词栏 | 评分 | ❌ |
| `my_units[].can_attack` | bool | 攻击令牌 + 未击晕 | 攻击候选 | ❌ |
| `my_units[].challenger` | bool | 挑战者图标 / 伊莉丝是否升级 | 攻击声明模式 | ❌ |
| `enemy_units[].stunned` | bool | 击晕图标 | 格挡合法性 | ❌ |
| `enemy_units[]` | list | 敌方场面 | 求解器输入 | ❌ |
| `nexus_hp` / `enemy_nexus_hp` | int | 水晶旁数字 | 斩杀/保命 | ❌ |
| `has_attack_token` | bool | 右下剑盾图标 | 攻击声明 | ❌ |

> `challenger` 与 `stunned` 是这套牌的**硬需求**：伊莉丝升级后全体蜘蛛获得挑战者，
> 蜘蛛哨兵/蜘術士靠击晕控场。求解器已经把两者建模（`best_blocking(chooser=...)`、
> `Combatant.stunned`），但感知层还没解析。

## 八、分层边界（v2）

| 层 | 负责什么 | 延迟 | 覆盖 |
|---|---|---|---|
| L1 规则 + 精确解 | 守卫、换牌、攻击声明、格挡声明、目标选择、贪心出牌 | <10ms | 大头 |
| L2 JEV | 出牌阶段的**语义判断**：效果文本值不值得现在出 | 100–500ms | 剩余部分 |
| L3 LLM | L2 也不确定时兜底 | 2–20s | 极少 |

**v1 定的「L2 占 15–25%」是拍脑袋的数字，v2 不再追这个比例。**
把可枚举的决策挪进 L1 之后，L2 的占比会自然下降——这是好事，不是坏事。
真正该看的指标是：**L2 命中时的胜率是否高于 L1 默认选择**。如果一样，说明 L2 白花钱。

同理，v1 的「L1 弃权率 20–30% 健康」也要改：弃权只发生在 P4 出牌阶段，
健康值取决于「出牌阶段真正模糊的比例」，必须实测，不能先定数字。
