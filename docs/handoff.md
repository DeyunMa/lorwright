## 下一步的判断边界

1. **回应当前机制评估。** 区分时机问题与错误后验：Jinx 回血是结果条件问题，选目标后的结算背景是阶段观察窗口问题；不要把所有停止统一解释为需要重发输入。
2. **观察重试与动作重试分别设计。** 优先在阶段内采新帧，核对相关独立证据及稳定性；已发送动作保留原记录。仅有可靠未执行证据或幂等交互时才考虑有界输入重试。不得反复刷新同一等待来取消硬截止。
3. **若获授权实施，沿现有 seam 收敛。** 继续使用 Reading、ActionOutcome、NEEDS_INPUT、Engine/AdventureLoop 阶段交接和 RunSession；保留父出牌的后验及预算。先建立能复现实际早判/晚判的合成与实拍回归，再本地验证、同步 f1、局部实机。未知 UI 不点击，局部未知不阻塞无关动作。
4. **若继续冒险，先确认现场。** 查会话、进程和新帧；当前是任务/经验结算，尚无明确继续按钮。仅按识别到的后继处理，不假定已回图或开始新冒险。完整无人值守验收另行安排。
