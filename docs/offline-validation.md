# 基础场景与离线验收

先把截图中的情况归纳成可重复验收的基础场景，再做实机验收和英雄打法。
核心负责识别、输入结果与安全边界；英雄包负责牌表、星力与打法取舍。

## 截图放在哪里

- 原始对局截图：`tests/fixtures/screens/`，可按游戏版本、日期建立子目录。
- 人工核对的预期值：`tests/fixtures/cases/*.json`，格式见同目录 README。
- 敏感原图、大批录制与诊断日志：仓库外的 `lorwright-artifacts/`，不直接提交。

已纳入 10 个历史单图案例，覆盖 UI、法力/血量、手牌费用/展开态、单位数量。
只标注已核实字段。每张图单独解析，不允许前图缓存掩盖本图读数失败。
历史标定随案例保存；它们不是新版 LoR 验收，也不是一次连续操作。

## 三类证据

| 案例 | 验证什么 | 不能证明什么 |
|---|---|---|
| 真实单图 + 预期状态 | UI、数字、位置识别 | 手势实际生效 |
| 明确标为合成的状态/图像序列 | 等待、超时、禁止重复输入、遮挡处理 | 现场延迟与真实交互 |
| 同一次操作的真实连续帧 + 动作记录 | 输入前后状态及成功率 | 其他版本/设备仍然可靠 |

后续按“手牌收起/展开、付费出牌、零费出牌、需要目标、攻击声明、格挡声明、
确认、动画遮挡、UNKNOWN、读数失败”组织案例。真实连续帧还需保留动作和时间；
不能把不同场次的单图拼成实测过程。

## 动作结果

`loop/outcome.py` 观察一次已发出的动作，主循环在等待期间只截图，不重新决策或发输入。
使用单调时钟和 `loop.action_timeout_s` 硬截止；过期帧不能作为成功证据。

| 动作阶段 | 当前接受的证据 |
|---|---|
| 收起态 PLAY_CARD（展开） | 新帧识别出展开手牌 |
| 展开态 PLAY_CARD（拖牌） | 手牌减少且本帧法力减少；或同种手牌展示状态下手牌减少且单位数增加 |
| 拖牌进入 TARGETING | `needs_input`，交回策略处理目标选择，不宣称已经出牌成功 |
| ATTACK / BLOCK | 前后单位总数一致，所选数量的单位上移进入声明行 |
| SELECT_TARGET / CANCEL | 已识别的 TARGETING 退出到另一个已识别状态 |
| CONFIRM / END_TURN | 已识别 UI 变化，或新读到法力增加 |
| CONFIRM 攻击 | 也接受令牌消失且单位归位的组合证据 |

攻击/格挡的后验只表示看到了换行，不证明格挡合法、对象正确或战斗胜利。
位移门槛 `loop.combat_row_min_move_px` 按设计尺寸计算。
`layout.my_combat` 补足旧配置不覆盖的己方声明行；只在手牌未展开且 UI 为
MY_TURN_IDLE / BLOCKING / COMBAT_RESOLVING 时识别，避免把预览大卡算作单位。
当前区域与位移阈值仍需新版游戏的真实连续帧验收。

超时记录 `action_outcome`、前后状态摘要及读数证据，保存 `action_timeout` 截图，
停止主循环；不自动重发输入、不重启游戏。等待期间遇到 UNKNOWN 也不点击。
UNKNOWN 的执行禁止由主循环保障，不依赖英雄策略正确实现。

限制：零费非召唤法术只有手牌减少时仍不足以确认；确认后若 UI 回到相同状态，
且没有其他已支持的变化，也会超时。错误选目标不会再自动猜另一阵营。
这些是保守停止的待验场景，不能说成完整交互能力已验证。

## 读数有效性

`GameState.readings` 为 mana / nexus_hp / enemy_nexus_hp 记录：

- `value=null, age_frames=null`：从未读到。
- `age_frames=0`：本帧读到，包含真正的 0。
- `age_frames>0`：缓存，表示距最近成功识别经过的解析帧数，不是秒数。

原数值字段暂保留最近值供展示；缓存不代表当前事实。主循环在 MY_TURN_IDLE /
BLOCKING 下要求三项数字均为本帧读数，否则 NO_OP；未来直接调用策略/求解器的
代码同样需要尊重 readings，不能只拿展示值作决策。
UNKNOWN / BATTLE_END 不从未知位置刷新数字。进入新一轮 MULLIGAN 清除上局缓存。
`lorwright state` 同时显示数字的观测状态，避免把默认显示值误当成读取成功。

## 本地检查与之后的实机验收

```sh
rtk proxy .venv/bin/python -m pytest -o addopts= -q
rtk proxy .venv/bin/ruff check src tests tools
```

还修复了空白/稀疏图像中带掩膜模板匹配产生 NaN/Inf 导致假手牌的问题；
相关测试用真实徽章裁片构造已知位置的图像，不将其冒充实机画面。

模拟器能进入 LoR 后，先只采上述缺失的真实连续场景，核对读取值、声明行范围、
动作结果与等待上限。单点能力验收后再跑短段战斗，再完善伊莉丝英雄规则；
不要用反复跑整局代替基础场景定位。
