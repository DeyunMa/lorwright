# 基础场景与离线验收

先把截图中的情况归纳成可重复验收的基础场景，再做实机验收和英雄打法。
核心负责识别、输入结果与安全边界；英雄包负责牌表、星力与打法取舍。

## 截图放在哪里

- 当前回归图片：`tests/fixtures/` 下的场景目录；新增素材只保留不含账号等敏感内容的原帧或原生裁剪，来源见 [`../tests/fixtures/README.md`](../tests/fixtures/README.md)。
- 人工核对的预期值：`tests/fixtures/cases/*.json`，格式见同目录 README；有具体行为的回归也可直接写在对应测试中。
- 含账号的完整战斗图、敏感原图、大批录制与诊断日志：已忽略的 `logs/` 或仓库外 `lorwright-artifacts/`，不直接提交。

已纳入 10 个历史单图案例，覆盖 UI、法力/血量、手牌费用/展开态、单位数量。
只标注已核实字段。每张图单独解析，不允许前图缓存掩盖本图读数失败。
历史标定随案例保存；它们不是新版 LoR 验收，也不是一次连续操作。

## 证据层次

| 案例 | 验证什么 | 不能证明什么 |
|---|---|---|
| 真实单图 + 预期状态 | UI、数字、位置识别 | 手势实际生效 |
| 明确标为合成的状态/图像序列 | 等待、超时、禁止重复输入、遮挡处理 | 现场延迟与真实交互 |
| 同一次操作的真实连续帧 + 动作记录 | 输入前后状态及成功率 | 其他版本/设备仍然可靠 |
| 局部实机运行 | 当前版本、设备和场景下的实际输入及后继 | 整个冒险全程无人介入 |
| 完整无人值守冒险 | 从约定初态到最终结果的连续自主推进 | 其他英雄或未覆盖环境也通过 |

后续按“手牌收起/展开、付费出牌、零费出牌、需要目标、攻击声明、格挡声明、
确认、动画遮挡、UNKNOWN、读数失败”组织案例。真实连续帧还需保留动作和时间；
不能把不同场次的单图拼成实测过程。

## 多冒险截图对照

`tools/audit_corpus.py` 可以重复扫描夹具、历史截图和地图样本，并按图片 SHA-256 对照结果。用同一版脚本、同一批输入、各版本自己的配置和识别资产分别运行。`--dir` 可重复传入，`--out` 保存逐图结果，`--compare` 列出两边未配对的样本和输出变化。避免在报告生成后移动或改写所用的输入图。

本轮回归包括三个周常的开局与早期节点、第三个周常的首领翼章和白银宝库两阶段，以及过往的治疗、商店、占星家、弃牌与战斗截图。已核实的读数、场景和动作候选见 `tests/test_audit_corpus.py`，地图点击顺序和结算后继见 `tests/test_adventure.py`。

逐图记录包含场景分类、已读数字及地图可达节点。战斗候选另记录当帧证据缺项和能否生成输入计划。汇总的 `actionable` 是局部启发式信号。动作就绪还依赖连续新帧及运行时流程。地图输入仅按原生 1920×1080 验证，缩放或恢复裁剪后的图仅用于感知对照。

## 动作结果

`loop/outcome.py` 观察一次已发出的动作，主循环在等待期间只截图，不重新决策或发输入。
使用单调时钟和 `loop.action_timeout_s` 硬截止；过期帧不能作为成功证据。

| 动作阶段 | 当前接受的证据 |
|---|---|
| 收起态 PLAY_CARD（展开） | 新帧识别出展开手牌；若明确进入待确认的结算状态，交接确认策略而不通知出牌成功 |
| 展开态 PLAY_CARD（通用拖牌） | 手牌减少，且新鲜普通/法术法力减少，或已识别状态下己方单位增加；英雄专属后验优先 |
| 拖牌进入 TARGETING / OPTIONAL_CHOICE / 待确认结算 | `needs_input`，交回已支持的交互策略，不宣称原出牌成功 |
| COLLAPSE_HAND | 前后均为己方行动，手牌从展开变为收起；下一帧重新识别和决策 |
| ATTACK / BLOCK | 前后单位总数一致且所选数量的单位上移；或明确进入 COMBAT_RESOLVING |
| SELECT_TARGET / CANCEL | 已识别的 TARGETING 退出到另一个已识别状态 |
| SKIP_CHOICE | 已识别的 OPTIONAL_CHOICE 退出到明确的战斗后继 |
| CONFIRM / END_TURN | 已识别 UI 变化，或新鲜法力增加；确认提示切换、同视图下新鲜敌军检出增加等支持路径返回 `needs_input` |
| 出牌的附加 CONFIRM | 确认和原出牌分别核验、分别记录；原出牌保留原预期及截止，允许后续帧补足结果，不再次拖牌 |
| CONFIRM 攻击 | 也接受令牌消失且单位归位的组合证据 |

Jinx 召唤和火箭由英雄包提供专属后验。召唤跨手牌视图时需要单位增加、新鲜支付及伤害并回到己方行动；火箭收手后要求己方行动，接受新鲜伤害或覆盖实际费用的新鲜净支付。两种视图的牌数不直接比较；同为展开态使用对应手牌变化规则。具体条件见 `core/champions/jinx/policy.py`，新鲜读数和策略计数边界有独立回归。

攻击/格挡的后验只表示看到了换行，不证明格挡合法、对象正确或战斗胜利。
位移门槛 `loop.combat_row_min_move_px` 按设计尺寸计算。
`layout.my_combat` 补足旧配置不覆盖的己方声明行；只在手牌未展开且 UI 为
MY_TURN_IDLE / BLOCKING / COMBAT_RESOLVING 时识别，避免把预览大卡算作单位。
当前区域与位移阈值仍需新版游戏的真实连续帧验收。

超时记录 `action_outcome`、前后状态摘要及读数证据，保存 `action_timeout` 截图，
停止主循环；不自动重发输入、不重启游戏。等待期间遇到 UNKNOWN 也不点击。
UNKNOWN 的执行禁止由主循环保障，不依赖英雄策略正确实现。

限制：零费非召唤法术只有手牌减少时仍不足以确认；确认后若 UI 回到相同状态，
且没有其他已支持的变化，也会超时。错误选目标不会再自动猜另一阵营。
这些是保守停止的待验场景，不能说成完整交互能力已验证。

## 读数有效性

`GameState.readings` 为 mana / spell_mana / nexus_hp / enemy_nexus_hp 记录：

- `value=null, age_frames=null`：从未读到。
- `age_frames=0`：本帧读到，包含真正的 0。
- `age_frames>0`：缓存，表示距最近成功识别经过的解析帧数，不是秒数。

原数值字段保留最近值供展示；缓存不代表当前事实。主循环给决策使用的过期普通法力
标为 `-1`、过期法术法力标为 `None`，并按所选动作检查必要证据。付费出牌需要
新鲜支付依据，0 费牌不依赖法力；攻击、格挡、确认和结束回合不统一等待血量或
无关读数。直接调用策略/求解器的代码同样需要尊重 readings，不能只拿展示值决策。
UNKNOWN / BATTLE_END 不从未知位置刷新数字。进入新一轮 MULLIGAN 清除上局缓存。
`lorwright state` 同时显示数字的观测状态，避免把默认显示值误当成读取成功。

`GameState.readings` 另用 `my_units_visible / enemy_units_visible` 记录本帧检出数量下界；零检出或未知 UI 返回未知，不缓存旧数量，不证明空场或集合完整性。`test_engine_outcome.py::test_real_parsed_opponent_board_reroutes_engine` 使用两张不同战斗实拍作后态，前态删减单位以隔离 0→1 / 1→2 的重新路由；这是实际感知到 Engine 的组合回归，不是连续录像。确认后的延迟支付、原截止、多个确认和无重复输入由合成序列覆盖。
