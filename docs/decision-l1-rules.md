# L1 规则层：通用设计

> 历史设计记录：其中 L2/L3、旧状态解析进度和拟议分派方式不代表当前实现。
> 现行纯脚本决策见 [ADR-0004](adr/0004-pure-script-decision.md)，
> 实际策略顺序见 `main._battle_layers`，进度见 [status.md](status.md)。

**定位**：确定性决策。**凡是能精确求解的，都不该进 L2。**

这份文档只讲**与英雄无关的机制**。每个英雄的牌表、评分公式、专属规则
放在 `docs/champions/<name>.md`。

```
src/lorwright/
  decide/
    base.py     Policy 协议（所有层都实现它）
    card.py     卡牌通用词汇（CardKind / CardDef）
    combat.py   战斗求解器（格挡分配、攻击声明）
    router.py   分层路由
  champions/
    __init__.py      按名字动态加载
    base.py          ChampionPack 协议
    elise/           伊莉絲：牌表 + 策略
```

**核心层不认识任何具体英雄。** 加一个英雄 = 加一个目录，不改 `decide/`。

## 一、先纠正一个前提：LoR 不是「回合制」

LoR 用的是**交替优先权（alternating priority）**，不是「我的回合 / 对手的回合」。

| 界面状态 | 含义 | 我能做什么 |
|---|---|---|
| 大蓝按钮 + 文字「結束回合」 | 我持有优先权，且对手已让过 → 按下即结束本轮 | 出牌、攻击、结束回合 |
| 大蓝按钮 + 文字「略過」 | 我持有优先权，但对手还没让过 → 按下只是把优先权交给对手 | 出牌、攻击、让过 |
| 没有蓝按钮 / 按钮变暗 | **对手持有优先权** | **没有合法动作** |

所以：

- **「不是我的回合就不操作」是对的**——不是你保守，是规则上没有合法动作。
- 但写成「弃权（返回 `None`）」是**错的**。没有优先权时答案唯一，就是 `NO_OP`。
  弃权会让路由把请求继续送到 JEV / LLM，**在对手回合每一帧白烧一次网络调用**。
  → **守卫必须 `return Action(NO_OP)`，不是 `None`。**
- 状态名 `MY_TURN_IDLE` 也是错的：它实际表示「我持有优先权」。对手回合里
  我拿到响应窗口时按钮同样变蓝——那是同一个状态。应该叫 `MY_PRIORITY`。

**待验证**（真机上做）：点「略過」后是否立刻进入敌方动作。若是，则「略過 = 我方优先权」成立。

### 一个连带 bug

`Watchdog` 用 `state.summary()` 判卡死。对手回合连续 3 帧 `NO_OP` 时摘要不变 →
会被判成「卡住」，刷快照甚至触发重开。**`NO_OP` 不应计入卡死计数。**

## 二、结构：按决策点分派，不是扁平优先级列表

扁平优先级列表表达不了「格挡阶段斩杀规则无意义」。改成：

```
P0 守卫      → 我在哪个决策点？（优先权 / 换牌 / 出牌 / 攻击 / 格挡 / 选目标）
P1 换牌
P2 攻击声明   ← 精确解
P3 格挡声明   ← 精确解
P4 出牌       ← 唯一真正需要 L2 的地方
P5 目标选择   ← 精确解
```

### P0 守卫

```
if ui_state != MY_PRIORITY: return NO_OP          # 没有优先权，唯一合法动作
if 换牌界面:              → P1
if 攻击声明界面:          → P2
if 格挡声明界面:          → P3
if 需要选目标:            → P5
if 我方优先权:            → P4
```

**起手换牌界面当前会被误判成「我方优先权」**（「確定」按钮和动作按钮位置重叠，
见 `docs/status.md`）。这是 P0 必须先修的 bug——否则开局第一秒机器人就会去点牌。

## 三、把「可枚举的」变成精确解

让 L1 吃掉更多，靠的不是加 if，而是把可判定的子问题变成穷举。
LoR 的动作空间小到可以穷举：

| 决策点 | 搜索空间 | 规模 | 实测（6v6） | 归属 |
|---|---|---|---|---|
| 格挡分配 | ≤6 格挡者 → ≤6 攻击者 | ≤ 13,327 种分配 | 17 ms | **L1 精确解** |
| 攻击者子集 | 2^6−1 = 63 种声明 × 对手最优格挡 | 63 × 13k | 23 ms | **L1 精确解** |
| 斩杀判定 | 同上，取最大脸伤 | 免费 | 24 ms | **L1 精确解** |
| 法术目标 | ≤6 | 6 | <1 ms | **L1 精确解** |
| 换牌 | 2^4 = 16 | 16 | <1 ms | **L1 精确解** |
| 本回合怎么花光法力 | 手牌子集 × 顺序 | 组合爆炸 | — | 贪心 + L2 兜底 |

（实测环境：Python 3.11 / M 系列 Mac。6v6 是最坏情况，24 ms，tick 预算 200 ms
——**穷举比启发式既准又便宜，没有理由不穷举**。）

### 战斗求解器（`decide/combat.py`）

支持关键词：普通 / 灵巧 / 恐惧 / 挑战者 / 碾压 / 快速攻击 / 坚韧 / 击晕。

- 格挡合法性：被击晕的单位不能格挡；灵巧攻击者只能被灵巧挡；恐惧攻击者只能被攻击力 ≥3 的挡
- 快速攻击：若先手伤害足以击杀格挡者，则不受伤
- 坚韧：受到的伤害 −1
- 碾压：对格挡者的溢出伤害穿透到水晶
- 未被格挡：全额攻击力打到水晶

**守方目标（字典序）**：先最小化自己水晶受到的伤害，再最大化「我方存活价值 − 对方存活价值」。
**攻方目标**：最大化「打出的脸伤 − 我方损失价值 + 对方损失价值」。

`best_blocking(chooser="defender" | "attacker")` 切换由谁分配：
默认守方选；**全体带挑战者时由攻方选**（这时攻方可以指定谁挡谁）。

**关键收益**：斩杀判定不再是手写规则，而是求解器的副产品 ——
不会出现「规则说能斩、求解器算出不能」的自相矛盾。

## 四、状态字段硬依赖

规则再漂亮，字段解析不出来就是空转。当前 `Engine._build_state()` **只填了 `ui_state`**，
其余全是默认值（`mana=0`、`hand=[]`、`my_units=[]`、`hp=20/20`）——
所以策略实际上永远走「手牌为空 → 结束回合」。这是 issue #4 的根因。

| 字段 | 类型 | 来源 | 用途 | 状态 |
|---|---|---|---|---|
| `ui_state` | 枚举 | 颜色探针 | P0 守卫 | ✅ 已有 |
| `button_text` | 結束回合/略過 | 按钮文字 OCR | 是否结束本轮 | ❌ 待做 |
| `mana` / `max_mana` | int | 右侧数字 | 可出牌判定 | ❌ |
| `hand[].cost` | int | 卡面左上 | 费用过滤 | ❌ |
| `hand[].kind` | 单位/法术 | 卡面边框色 | 分流 | ❌ |
| `hand[].keywords` | set | 卡面关键词栏 | 评分 | ❌ |
| `my_units[].can_attack` | bool | 攻击令牌 + 未击晕 | 攻击候选 | ❌ |
| `my_units[].challenger` | bool | 挑战者图标 / 英雄升级状态 | 攻击声明模式 | ❌ |
| `enemy_units[].stunned` | bool | 击晕图标 | 格挡合法性 | ❌ |
| `enemy_units[]` | list | 敌方场面 | 求解器输入 | ❌ |
| `nexus_hp` / `enemy_nexus_hp` | int | 水晶旁数字 | 斩杀/保命 | ❌ |
| `has_attack_token` | bool | 右下剑盾图标 | 攻击声明 | ❌ |

## 六、分层边界

| 层 | 负责什么 | 延迟 | 覆盖 |
|---|---|---|---|
| L1 规则 + 精确解 | 守卫、换牌、攻击声明、格挡声明、目标选择、贪心出牌 | <10ms | 大头 |
| L2 JEV | 出牌阶段的**语义判断**：效果文本值不值得现在出 | 100–500ms | 剩余部分 |
| L3 LLM | L2 也不确定时兜底 | 2–20s | 极少 |

**v1 定的「L2 占 15–25%」是拍脑袋的数字，不再追这个比例。**
把可枚举的决策挪进 L1 之后，L2 的占比会自然下降——这是好事。
真正该看的指标是：**L2 命中时的胜率是否高于 L1 默认选择**。如果一样，说明 L2 白花钱。

同理，「L1 弃权率 20–30% 健康」也要改：弃权只发生在 P4 出牌阶段，
健康值取决于「出牌阶段真正模糊的比例」，必须实测，不能先定数字。

## 七、英雄专属部分在哪

| 内容 | 位置 |
|---|---|
| 牌表、卡牌效果分类、卡名别名 | `src/lorwright/champions/<name>/deck.py` |
| 出牌评分、出牌顺序规则、这套牌的取舍 | `src/lorwright/champions/<name>/policy.py` |
| 牌组说明、星力、这套牌的特殊机制 | `docs/champions/<name>.md` |

**加英雄的检查清单**：

1. 建 `src/lorwright/champions/<name>/`，写 `deck.py`（继承 `CardDef`）+ `policy.py`（实现 `Policy`）
2. `__init__.py` 里暴露 `PACK`
3. `config/settings.yaml` 把 `champion` 改成新名字
4. **不改 `decide/` 下任何文件** —— 如果需要改，说明有东西没抽象干净
