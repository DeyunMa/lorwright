## 目标与已确认原则

`core/` 自主完成识别、决策、执行、验证和后续推进；CLI 用于启动、观测、控制，Agent 在开发期补能力。GUI 待整体能力稳定后再做。

基础验收目标是 Jinx 和 Elise 分别全自动完成整个冒险，目前均未端到端验证。局部未知只限制依赖动作，不要求冒险中新卡全部建档；可跳过未知牌继续已知动作，接受少赚收益，英雄或组合优先不能无限阻塞普通动作。UI、交互或动作结果未知时有界等待，期限到达保存截图并停止。

## 本轮闭环调整

以下闭环调整已提交为 `1bd77a5`，并通过 `13e70a4` 合入 `main`、同步至 f1：

- `None` 弃权与 `NO_OP` 等待分离；未知牌及不可执行的 Jinx 起手/火箭偏好不阻挡通用动作。可执行火箭仍优先；Elise 未知牌仅在有可出单位证据时参与出牌排序。
- Engine 按动作检查必要证据：过期法力不用于支付，0 费牌无需法力读数；可独立证实的法术法力可用于相应法术。攻击、格挡、确认和结束回合不统一依赖法力/血量。
- 持续未知、缺少动作前提、无动作、无法生成输入计划及等待对方均有截止；到期核心自行存图停止，不依赖 CLI 查询，不重放旧计划。已发送的结束回合输入也必须核验，超时不自动重发。
- CLI 状态新增 `message` 和 `last_decision`，报告决策理由、未知牌槽位及输入/验证阶段；人读事件隐藏重复轮询，`--verbose` 和 `--jsonl` 保留完整事件，详情见 [`cli.md`](cli.md)。
