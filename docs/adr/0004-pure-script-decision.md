# ADR-0004：决策走纯脚本路线（MAA 式），不接 LLM/JEV

- 状态：**Accepted**
- 日期：2026-11-05（2026-11-06 补记）

## 背景

原架构设计里决策层是「规则 → JEV → LLM」三层路由：规则层处理
确定性场景，JEV（可验证执行）生成候选并自验，LLM 做界面分类兜底。
文档 docs/decision-l2-jev.md 记录了当时的接入契约。

## 触发

2026-11-05 实机连打月度挑战：状态解析不完整时 L3（LLM）空转、
JEV 候选为空，实际决策全部由规则层完成；同时用户明确方向是
**先有能力、后优化判断**，对齐 MAA/ALAS 的纯脚本资源包模式
（decide/ 只管机制，champions/ 管具体知识）。

## 决策

**删除 JEV/LLM 层**（decide/jev*.py、decide/llm.py 及
config/doctor/main 的装配），决策 = 规则层（decide/ 通用机制 +
champions/<name>/ 英雄包）。Router 分层结构保留，便于未来如果
复杂度真的需要，再以新形态引入。

## 后果

- 好处：无外部依赖、决策确定性可测（267 项单测不依赖游戏）、
  调试闭环全在本地，MAA 式英雄包即插件形态（ADR-0001 继续成立）。
- 代价：界面分类/异常兜底只能靠模板与规则；画面大改版时需要
  重采模板而不是「让模型看一眼」。用采集清单 + 基准回归对冲。
- docs/decision-l2-jev.md 保留为历史文档，标注已废弃。
