# 接手入口

更新基准：2026-11-15。先读本页与 [`status.md`](status.md)，命令协议查 [`cli.md`](cli.md)，职责与行为契约查 [`architecture.md`](architecture.md)。本页记录当前接手所需信息，不继续叠加旧时间线。

## 当前目标与边界

让 `core/` 自主完成识别、决策、执行、验证和推进；CLI 负责启动、观测和控制，Agent 在开发期根据证据补能力。基础目标是 Jinx、Elise 分别全自动完成整个冒险，当前均未端到端验证；GUI 待整体能力稳定后再做。

已批准的运行原则：局部未知仅限制依赖它的动作，不要求新卡全部建档；未知牌可跳过继续有依据的动作。接受少赚收益，英雄/组合优先不能无限阻塞普通动作。UI、交互、动作结果未知时有界等待，到期存图并明确停止；旧计划不能跨画面重放。

## 接手步骤

1. 核对本地工作区差异、当前代码与本轮实现报告，保留并行和用户改动。只有部署/实机授权覆盖目标时才连接或同步 f1；同步前核对并备份待覆盖内容，之后校验。
2. 查询明确 `RUN_ID` 的状态和增量事件，确认是否有活动会话、等待原因、最后进展与停止结果。没有活动会话时，获取实时画面确认当前 UI，再启动已支持流程。设备锁不约束 SYSTEM 看门狗或独立调试命令，避免同时控制。
3. 让程序连续处理已支持步骤，使用有界 `status --wait` 观测。看到阻塞先读决策/等待/停止原因，再查看关联截图。停止请求 ACK 后继续查终态；ACK 不代表手势已经中断。
4. 用新证据定位感知、策略、动作前提、执行或结果核验问题，修改最小必要能力并做针对性离线检查；在已有授权范围同步并继续实机验证。记录实际输入与结果，不把离线回放称为实机推进。

```bash
rtk lorwright sessions status RUN_ID --wait 30 --json
rtk lorwright sessions events RUN_ID --after 0 --jsonl
rtk lorwright sessions stop RUN_ID --json
```

首次事件查询用 `0` 或省略游标，后续使用实际最后 `seq`。会话启动、Jinx 中局参数、f1 准备及凭据选项见 [`cli.md`](cli.md)。

## 本轮已完成与验证

以下为本地实现与离线证据，尚未在 f1 实测：

| 项目 | 本轮结果 |
|---|---|
| 策略路由 | 未知牌跳过；Jinx 不可执行偏好弃权，实际交互等待仍为 `NO_OP`；Elise 未知牌需要可出单位证据 |
| 动作门控 | 过期法力在决策视图标为未知；出牌验证费用/位置/支付能力，攻击等独立动作不再统一等待法力/血量 |
| 有界等待 | 核心以单调时钟计时；未知、缺少动作前提、无动作、无有效输入计划及等待对方到期自行存图停止，查询不推进循环 |
| 恢复 | 不重放旧计划；动作结果超时停止，结束回合也不盲目重发；既有战斗安全停止交给冒险外层 |
| CLI 观测 | `message`、`last_decision`、`decision_reason`、`unknown_cards`、`input_sent`；阻塞原因及截图引用见 [`cli.md`](cli.md) |
| 验证 | 全套离线测试 975 passed，Ruff 与差异空白检查通过；合成战斗自主推进、有界等待及会话/JSONL 契约均已回归 |

先由用户审阅主要文档，再进入获授权的提交、同步和 f1 开发循环。后续运行前仍需重新确认现场；不能把本轮离线测试当作真实冒险通关。

## 关键能力缺口

- 弃牌仍是单次选择、截图后停止；完整确认、结果核验及转场未完成闭环。
- `--auto-login` 已有可选实现，真实账号登录尚未实测；模拟器关闭后的完整冷启动也未验收。
- 奖励、地图及战斗有部分局部实机记录，范围见 [`status.md`](status.md)；转场不证明奖励到账，人工确认/接管的成功不算全自动。
- 卡面、数值、目标及遮挡识别覆盖有限；未知单位视觉依据不代表所有新卡的效果、额外费用或交互都已理解。
- Jinx 与 Elise 各自完整自动冒险尚未端到端验证；不能声称所有异常可自动恢复。
